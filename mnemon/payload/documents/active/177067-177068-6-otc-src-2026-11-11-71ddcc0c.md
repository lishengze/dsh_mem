# 单客户应急回切 177067/177068：实现梳理与优化方案

本文只做路由与结论摘要，细节以仓内文档为准。

## 1. 功能定位

**客户级（明细级）应急回切**：把指定客户的资金账户从低延时（新 OTC）链路切回常规链路，同时修正 VIP 节点配置与残留夜市委托。
与 **110129 节点级回切**互补：110129 决定「节点是否处于应急/常规」（整体开关，落 `sys_config_cb`，主键 `vip_id=VIP{systemid}_{nodeid}`），
177067/177068 决定「哪些客户/资金账户切回」（个体执行）。两者数据表不重叠。典型顺序：110129 置节点应急态 → 177067 按名单逐客户回切 → 110129 恢复常规态。

## 2. 调用链与关键契约

参数中心异步调度 → KGMS → LBM `70177067`（8 步入口校验链）→ Atom `70177068`（读名单 / 逐客户处理 / 统计）→ BOS `960004`，topic `topic-otc-bos-1`。

| 契约点 | 结论 |
|---|---|
| 同步应答 | `row_count=0`，空结果集；`SetLbmSucc` 不被调用。调用方只能以 BOS 回报为准 |
| 177068 注册 | 未在 function.xml 注册，只能由 177067 进程内触发 |
| 名单文件 | 文件名 `YYYYMMDD_count_批次_域`（代码统一补 `.TXT`）；每行 6 字段，ASCII `0x01` 分隔；`custid` 去前 2 位、`fundid` 去前 6 位转短号 |
| 目录 | `sys_mixedconfig.khhqpath` |
| 处理粒度 | 每客户一个事务 |
| 异步回报关键字段 | `extersno`、`batchsno`（文件名第 3 段）、`execnum/succnum/failnum`、`dealflag`、`remark`、`returnmsg`，加信封字段 `g_funcid=170019`、`reqfunction=170068`、`systemid=89`、`action=U`、`timeout=10000`、`trustcode` |
| `dealflag` 三态 | 全成功 `'1'`；部分成功 `'2'`；全失败 `'0'`；**`execnum==0`（名单为空/全坏行）保持初值 `'0'`** |

## 5. 六项风险与优化方案（对应仓内 §11 / §16）

建议实施顺序：**O1、O2（正确性优先）→ O3（互通正确性）→ O5、O6（健壮性）→ O7（可运维性）**。

| 编号 | 问题 | 方案要点 |
|---|---|---|
| O1 | `ProcessOneCustomer` 更新 `switch_flag` 后又做调试性二次 `Select`，失败直接 `return false`，**事务已 Begin 却未 Rollback** | 推荐删除调试块；若保留校验，失败分支必须先 `Rollback()` 再返回 |
| O2 | `HandleCreditVipCustomers` 中 `InsertTrans` 失败只打 WARNING（`return false` 被注释）→ 删旧成功、插新失败，**记录丢失仍计成功** | 插入失败即 `return false`，由上层 `Rollback()`（删+插同事务，回滚恢复旧记录） |
| O3 | `CalcTrustCode()` 中互信密钥**硬编码**，旧系统读 `sys_mixedconfig.hxmagy` | 新增 `GetHxmagy()`（读配置 + `alltrim`，空/表不可用回退硬编码）；`CalcTrustCode()` 去 `const`，失败推送路径同样可回退 |
| O5 | 入口无条件 `+= ".TXT"`，上游传 `xxx.TXT` 变 `xxx.TXT.TXT` → 误报文件不存在 | 抽 `BuildListPath()`，**大小写不敏感**判断已带后缀；Atom 侧兜底拼接同规则 |
| O6 | `khhqpath + filename` 直接拼接，未过滤 `../`、分隔符、控制字符 | 两层：入口**先读原始值再校验**（`≤32`、无 `/` `\`、无 `..`、无控制字符）非法即 `PushBosFail`；Atom 侧 `realpath()` 前缀校验（须以 `realpath(khhqpath)` 为前缀且紧跟 `/`），越界抛 `-70177068104` |
| O7 | `remark` 固定只收 10 个失败账号，`failnum` 与列表对不上 | 按 `m_szRemark` 容量（`kdt_char1024` → 1024 字节）动态收集，超容截断加 `,...`，日志记录 listed/dropped |

### 方案设计中的两处关键事实修正（值得复用的教训）

- `m_szRemark` 是 `kdt_char1024` = `char[1025]`，容量按 **1024** 计，不是 1023。
- `m_szFilename` 是 `kdt_char32` = `char[33]`，且 `GetValue` **超长静默截断不报错** → 路径校验必须「先读原始值 → 校验 → 再写回成员」，否则截断后才校验会「看起来合法」。O5 与 O6 联动：`filename` 含后缀时整体长度仍须 ≤32。

### 外部依赖待确认

1. BOS / 参数中心 `remark` 字段长度上限（O7）；
2. 现场 `sys_mixedconfig.hxmagy` 是否已配置（O3，未配置则回退硬编码，行为与现状一致）；
3. `khhqpath` 是否为绝对路径（O6 的 `realpath` 前提）。

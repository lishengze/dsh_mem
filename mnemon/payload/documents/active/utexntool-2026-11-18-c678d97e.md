# UTEXnTool 抓包/绑核/配对工具链 — 结构与实测陷阱（2026-11-18）

范围：`tools/UTEXnTool/` 全套工具的体系化梳理（源码在 gt_trunk / gt_svn / gt_sit 三仓同构）。
权威正文在仓库内：`tools/UTEXnTool/doc/UTEXnTool分析报告_20261118.md`（839 行 / 16 章 / 4 张 Mermaid 图）。

## 1. 关键认知：其实是三套工具并存（新人最容易选错）

| 目录 | 血统 | 端口 | 配对方式 |
|---|---|---|---|
| `utexntool/`（根） | 信创 10.189.96.121 | 8885 / 8010 | `a.out` 固定字节偏移（232 / 326） |
| `utexntool/x86/` | Intel + Solarflare Onload | 同上 | 精确（需写 user_info）/ fuzzy（按长度） |
| `utexntool/a49/` | 49 适配，**当前主力** | 33001/33002、38140/39143 | `parse_nic` → `parse_stream4` 精确 |

分目录要素（`x86/Readme.txt`）：`tcpdump.sh` 为抓包（`onload_tcpdump ... --time-stamp-precision=nano -B 163840`，网卡名需改）、
`parse/` 精确匹配（`parse.sh` 上行 / `clean.sh`）、`fuzzy_parse/` 模糊匹配、`src/` 源码
（`t.cpp`→`a.out`、`b.cpp`→`b.out`、`fuzzy_parse.cpp`→`fuzzy_cal`、`analyze_delay.cpp`）。

## 2. 四层架构 + 进程内探针

- **L1 抓包**：tcpdump/onload_tcpdump + netns 隔离；
- **L2 绑核**：`pin_full_chain.sh`（全链路：客户端 / FTE / mock 交易所 / 模拟 SQL / 抓包）、`pin_fte_by_stack.sh`（线程级）、`UteBindCore/bind_core-81.sh`（血统来源）；
- **L3 配对**：`a.out`/`b.out` → `parse_nic.py` → `parse_stream2/3/4.py`；
- **L4 编排**：`run_capture_perf.sh` + `bin/fte_perf_capture`（AF_PACKET 在线实时关联）。
图中实线=当前主用，虚线=历史代。

## 3. 配对算法四代演进链（每代解决的具体故障）

```
a.out 固定偏移(232/326) → 错在「换环境偏移全错」
  ↓
parse_nic.py (msg_type + FIFO) → 错在「混入登录包即整体错一档」
  ↓
parse_stream2 (TCP 流重组)     → 解决「一个包 ≠ 一条消息」
  ↓
parse_stream3 (每端口各自头长)  → 解决「沪市 16B 头」
  ↓
parse_stream4 (按 client_seq_id 精确配对) → 彻底消除错位
```

- `t.cpp` 的端口/消息类型/偏移/位数全部来自 argv（`g_fte_port ... g_tgw_key_len`），`parse.sh` 里按 上海/深圳/深圳bond 三行注释切换参数；
- **结果可信度判据**：`parse_stream4.py` 打印的 `交集=N` 就是配对可信度——交集远小于包数说明 key 取错，此时**不要看时延**；
- **隐式依赖（局限 1）**：`parse_stream*.py` 用 `exec(open('/tmp/pcap_lib.py').read())`，路径写死 `/tmp/`，原地运行必失败，须先 `cp a49/pcap_lib.py a49/tcp_info_inc.py /tmp/`。

## 4. 绑核纪律（aarch64 鲲鹏920 / 256 核 / 4 NUMA，`cpu_config_remote.conf` 2026-10-31 校准）

- `isolcpus=64-127 irqaffinity=0-63`，**不加 nohz_full**：nohz_full 会让 epoll 唤醒退化（实测 277~474 µs）；
- 业务与内存全放 node1，热路径不跨 NUMA；io 与内部消息线程各占一个物理核（SMT 兄弟互抢 +2~3 µs）；
- mock_exch 放 io 核的 SMT 兄弟（loopback 软中断/唤醒留同物理核）；
- 抓包放同 NUMA 邻近核：69/70/71 最优，同节点更远 +0.6~0.7 µs，**跨 NUMA +4 µs**；
- 压测客户端必须整进程 `taskset`（只靠 `perf.cpu_id` 会让工作线程跑到 node3，+3 µs）；
- **不许按 CPU 占用排序绑核**：忙轮询线程占用会翻转导致角色错位（同配置 8.6 µs 与 11.3 µs 交替），必须用 `pstack` 按栈特征一次性识别后绑定；
- 优先级：命令行 > 环境变量 > 配置文件 > 脚本内置默认。

## 5. 九个已知陷阱（均有真实出处 svn_work/145~154）

- **缺 `TCP_NODELAY`** → Nagle 合并，时延 18.45 ms → 9.54 µs（147 号）；
- **报告对象池容量 2000 被打穿** → 池告警 8841→0，P50 38.5 → 13 µs（145 号）；
- **FIFO 配对系统性偏移 ≈ 1/4 发包间隔**，且必须**排除登录包（>200 字节）**；正式口径须用 `client_seq_id` 精确配对（146 号）；
- **三种口径不可混用**：`lo` 环回 7.95 µs ≠ 柜台能力；物理链路 42 µs；正确口径（网卡收 API → 网卡发交易所）**35 µs**（151~154 号）。用 `lo` 的 8 µs 回答客户"柜台时延多少"是错的；
- 其它：netns 残留、抓包核跨 NUMA、Onload `--time-stamp-precision` 未开、pstack 短时挂起、帧头长度假设等（详见报告 §九）。

## 6. 与跨机总结的对应（报告 §十六）

仓库内 130~154 号跨机文档与本工具的"设计点 / 已知缺陷"逐条对齐，两边可互相查证：绑核纪律 → L2 层设计；
配对演进 → L3 层；`TCP_NODELAY` 与对象池瓶颈 → 测量前提；三种口径 → 结果解读章节。

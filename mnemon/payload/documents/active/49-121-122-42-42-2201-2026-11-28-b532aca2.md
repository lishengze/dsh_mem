# 四台测试服务器连接方式与 42 端口 2201 开通（2026-11-28 实测）

环境：本机（lsz）→ 内网 10.189.x.x 测试机；配置与凭据位于 `work_store/work_sum/remote_data/remote_env.json|txt`，SSH 材料在 `~/.ssh/{config,id_ed25519}`。

## 1. 登录矩阵（本次三步实测：ICMP → TCP 端口 → 真实 SSH 登录）

| 主机 | 从本机 | 登录方式 | 实测档案 |
|---|---|---|---|
| 49 `10.189.111.49` | ✅ 直连 | `root@… -p 2201`（paramiko 读 work_store 存储密码） | `localhost.localdomain`，aarch64，**256 核**，up 8 天 |
| 121 `10.189.65.121` | ✅ 直连 | `root@… -p 2201` | `lingqu01`，aarch64，**344 核** |
| 122 `10.189.65.122` | ✅ 直连 | `root@… -p 2201`（**仅 root，无 lsz 用户**；密码同 121） | `lingqu02`，aarch64，**160 核**（4 NUMA） |
| 42 `10.189.111.42` | ⚠️ **22 不通、2201 本次才开通** | 稳定路径 `本机 → 49(2201) → ssh root@10.189.111.42:22` **免密** | `localhost.localdomain`，x86_64，**80 核**（20C×2 HT），CentOS 8 |

要点：
- 49 的 **22 端口对本站段关闭**，只有 2201 可用；42 的 22 只对同网段开放 —— 这是端口策略，不是宕机（`ping` 通但 TCP 全闭时不要判宕机）。
- 42 的 root 密码**没有记录**，历史上只有「49 免密跳板」这一条路；要新增直连需在 42 上追加本机公钥（本次已加，`/root/.ssh/authorized_keys.bak_lsz-dev-20261128` 为备份）。
- 42 网卡 `ens41f1np1 = 10.189.111.42/20`（网关 .254），另有 `ens41f0np0 = 192.168.88.1/24`。
- **档案会过时**：`remote_env.json` 记 49 为「Kunpeng 920 194 核」，实测 `nproc` = 256（与 `svn_work/01-环境与部署/01_环境与构建.md` 一致）⇒ 该表**连接方式可信、硬件参数须现场取**。

## 2. SSH 不可达的分层定界法（可复用）

1. ICMP：判网络可达性；丢包 0% 只证明 IP 层通。
2. TCP：`/dev/tcp` 或 python socket 探测目标端口。
3. 卡在 TCP 时，**在目标机上抓包**，边从源端发起连接：
   - 抓到 `SRC → 目标:port [S]` 但**无 SYN-ACK** ⇒ SYN 已到达，是本机（防火墙/策略）丢弃，可排除上游 ACL；
   - 若目标机抓不到 SYN ⇒ 问题在中间网络/路由。
4. 端口通但登录失败时才看 sshd：`sshd_config` 的 `Port`、`ss -lntp` 监听、SELinux `ssh_port_t`、`authorized_keys` 权限/SELinux 上下文（`ssh_home_t`）。

## 3. 案例：42 的 2201「以为要配 sshd，实际是防火墙」

排查结果逐层排除：

| 层 | 42 实况 | 判定 |
|---|---|---|
| `sshd_config` | 已有 `Port 22` + `Port 2201` | 早配好，无需新增 |
| 监听 | `0.0.0.0:22`、`0.0.0.0:2201` 均在听 | 正常 |
| SELinux | Enforcing，`ssh_port_t` 已含 `2201, 22` | 无需 `semanage` |
| **firewalld** | public zone **缺 `2201/tcp`** | ★ 根因 |

落地动作（均幂等、有备份）：`firewall-cmd --permanent --zone=public --add-port=2201/tcp` → `firewall-cmd --reload` → `sshd -t` → `systemctl restart sshd`；验证本机 `42:2201` OPEN 且可 root 登录，49→42:22/2201 保持 OPEN。

## 4. ⚠️ `firewall-cmd --reload` 会用 permanent 覆盖 runtime（本次踩坑）

42 原有 4 个端口只活在 runtime、未写入 permanent（`38140/tcp 38141/tcp 39143/tcp 39144/tcp`，模拟交易所/模拟 SQLServer），reload 后**当场从运行期消失**，已补 permanent 并复原。

复用判据（reload 前必须为空）：
```bash
diff <(firewall-cmd --permanent --zone=public --list-ports | tr ' ' '\n' | sort) \
     <(firewall-cmd --zone=public --list-ports            | tr ' ' '\n' | sort)
```
另外：端口在 zone 里但无监听 ⇒ 是服务没起，不是防火墙问题（本次 38140/38141/39143 即属此类）。

## 5. 回滚

```bash
# 撤销 42 的 2201 放通
firewall-cmd --permanent --zone=public --remove-port=2201/tcp && firewall-cmd --reload
# 撤销本次追加的公钥（经 49 跳板执行）
sed -i '/lsz-dev-20261128/d' /root/.ssh/authorized_keys
# sshd_config 本次只重启未改内容；如确需还原用 sshd_config.bak_20261128_* 覆盖后 restart
```

# Kafka 推送 JSON 封套切换为老系统对外模板（SRC/MSG_TYPE/MSG_SUBTYPE/SEND_DATE/SEND_TIME/MSG_ID/TARGET/CONTENT）

实施日期：2026-11-06　提交：`052266f8 feat(kafka): 推送 JSON 封套改为老系统对外模板`（27 文件，+549/−171，已推 origin dev，同步 0/0）

> 本文取代此前文档中对"旧封套"（`schema/table/op/funcid/sys_id/as/ts/ts_str/data`）的描述。JSTP 字段体的**字节布局与解析纪律不变**，见文档 `12e794ba-aff6-4507-b5a0-a69b9fb58eb3`（逐字节格式：varint 长度域）与 `80ee5b2f-0239-4350-99fe-706465a22fcc`（报文头 10/11/12 字节、Topic/XA 配置）。这两份文档中的 JSON 封套字段清单已过时，其余结论仍有效。

## 1. 新封套（对外契约）

```json
{
  "SRC": "", "MSG_TYPE": "otc_seriesinfo", "MSG_SUBTYPE": "otc_seriesinfo",
  "SEND_DATE": 20261106, "SEND_TIME": 81240,
  "MSG_ID": "", "TARGET": [],
  "CONTENT": { "of_code": "TESTFWD", "ta_code": "1", "...": "..." }
}
```

| 字段 | 取值规则 |
|---|---|
| `SRC` | 恒空串（老模板保留位） |
| `MSG_TYPE` / `MSG_SUBTYPE` | 均为内存库表名，**取代 `table`**，下游据此选 schema |
| `SEND_DATE` | YYYYMMDD 整数 |
| `SEND_TIME` | HHMMSS 整数，**无前导零**（`81240` = 08:12:40） |
| `MSG_ID` / `TARGET` | 恒空串 / 恒空数组 |
| `CONTENT` | 记录本体（原 `data`），输出表的全部列，空串与 0 不省略 |

旧字段 `schema`(`kgbp.record.v1`)/`op`/`funcid`/`sys_id`/`as`/`ts`/`ts_str` **不再输出**。JSTP 报文头（`ca 01` + varint 描述符 + `RECORD` + varint 长度）不变。

## 2. 改动范围：只有一个函数

封套集中在 `otcsrc/public/comm/kafka_record_forwarder.h` 的 `AppendHead()` 生成；业务代码与 `kafka_insert_hook.h` 钩子逻辑**零改动**。这是该设计的收益：换协议模板不触碰业务侧。

## 3. 下游必须同步的三处硬编码

1. 取 JSON 的标记 `{"schema"` → **`{"SRC"`**（旧标记在新格式下彻底失效）
2. `doc["table"]` → **`doc["MSG_TYPE"]`**
3. `doc["data"]` → **`doc["CONTENT"]`**
4. 风险项：若下游依赖 `op`（增删改）或 `ts`（毫秒时间戳），新模板**无对应字段**，需要单独确认补偿方案（上游暂未提供）。

## 4. 验证结果

| 场景 | 结果 |
|---|---|
| 本地 127.0.0.1:9092 | 3 条消息键序一致，`MSG_TYPE` = trd_order / trd_appoint_order / sys_log_asset，`CONTENT` 字段数 97/60/49 |
| 跨服务器 10.176.218.99:9092 | 远端 broker 收到新格式，`SEND_DATE=20261106`、`SEND_TIME=73402`，用例 pass=1，`forward failed` 0 |
| 全量编译 | `compile.sh` 36 分 08 秒，0 error；部署重启后复测 pass=1、格式正确 |

实测报文前缀长度 11 字节（JSON 起点落在 `{"SRC"`），与旧格式时期的 10/11/12 三档结论一致——**仍不可硬编码偏移**。

## 5. 对端 Kafka 部署踩坑（可复用）

远端 10.176.218.99 有 docker（`otc` 容器 host 网络）但无 Kafka、无 Java，且外网不通 Docker Hub。做法：本机 Kafka(114MB)+JRE(61MB) 打包 scp（约 18 秒），远端跑 KRaft 单节点。

- **坑 1**：JRE 的 `jre/lib/tzdb.dat`、`jre/lib/security/cacerts` 是指向 `/usr/share/...` 的符号链接，远端缺目标文件 → Java 启动即 `FileNotFoundException: tzdb.dat`。需补传真实文件覆盖。
- **坑 2**：`advertised.listeners` 必须写对方可达 IP；写 `127.0.0.1` 会表现为"bootstrap 成功但拉元数据失败"。

# gt_sit（生产分支 r87165）本地 docker 复测：功能对齐、性能不可引用（2026-11-05）

关联文档：gt_svn 侧复测结论见 `9e861d20-7da8-4980-a9c5-34e5fcbae404`（ETF 缺失、性能样本恒 341）。本文补的是**生产分支 gt_sit** 的本地复测，两者结论不同，不可互相替代。

## 1. 结论

| 维度 | 本地 | 远程 | 判定 |
|---|---|---|---|
| 深市功能 | 8/8 | 8/8 | 一致 |
| 沪市功能 | 14/14 | 14/14 | 一致（远程 5 例 + 1 条静默用例 = 6 例/6 通过口径下的 14 项断言） |
| 性能六档 | P50 4.6~9.8 µs，outlier 47%~76% | P50 10.1~13.7 µs，outlier 0 | 本地**不可对外引用** |

功能侧本地 100% 复现远程；性能结论仍以远程隔离大机为准。本地性能复测只剩两点价值：链路能跑满（发送失败 0、出口包=发送数）、NO_DSE 补丁有效（50000 笔无 5461 卡死）。

## 2. 与远程手册的偏差（三条本地坑）

1. **`BUILD_ARM=1` 在本机是反效果**。远程手册要求先设，本地照做即链接失败：
   `/usr/bin/ld: skipping incompatible .../gte/lib/arm/libboost_system.a`。远程是 `lib/x86` 有问题、`lib/arm` 可用，本地相反；不设该变量走 `lib/x86` 即可（gt_svn 构建成功时同样未设）。
   => 手册中机器相关项必须本地实测，不能照抄。
2. **SIT 分支 spdlog bundled 缺 `core.h`**。`fte/include/tech/spdlog/fmt/bundled` 只有 13 个文件（gt_svn 为 14），编译报
   `fatal error: spdlog/fmt/bundled/core.h: No such file or directory`。从 gt_svn 侧整目录覆盖后解决。
3. **残留进程毁掉整轮性能数据**。首轮 outlier 56%~76%，根因是 `/mnt/work/gt_test/run/ute`（上一轮 gt_trunk 遗留）占 188% CPU，load average 133。
   `pkill -f 'u[t]e -n UTE'` **杀不掉守护进程**，必须按 PID kill；清理后 load 133 → 2.02，数据才可用。
   => 性能测量前先查 `uptime` + `ps -eo pcpu,args --sort=-pcpu`，确认无遗留 ute/mock_exch_server。

## 3. 沪市 14/14 的关键：用例间“静默排空”

本地原始沪市用例 5 条，撤单一直 FAIL（捕获到上一笔尾随成交回报导致串扰）。按远程方案在「成交回报校验」与「撤单」之间插入一条：

```json
{ "test_case": {"name": "等待回报静默（1.5s）"},
  "request":  {"type": "wait_silent", "silent_ms": 1500} }
```

客户端 `TestCaseRunner::send_request` 需支持 `wait_silent`（睡眠后校验连接仍在），并配套 `wait_for_etf_basket(timeout, want_sid)` 按证券过滤。加完撤单 FAIL → PASS，13 → 14/14。
这是把尾随回报在用例间排空，不是绕过校验。

## 4. 性能：本地数字为何不可引用

本地 P50 看似更低，实为分布被切成两簇：一簇 5~10 µs 快样本 + 过半 >100 µs 慢样本，P50 只落在快簇。根因是隔离度：远程 192 核 + `isolcpus=64-127`，本地 12 核 cpuset，5000 TPS 已接近饱和。
按自有协议 outlier > 5% 时 P50 不得对外引用，本地六档全超标。

| 档位 | 远程 P50 (µs) | 本地 P50 (µs) | 本地 outlier |
|---|---|---|---|
| 深 1000 | 10.16 | 4.62 | 56% |
| 深 2000 | 10.51 | 9.00 | 70% |
| 深 5000 | 10.07 | 5.15 | 76% |
| 沪 1000 | 13.64 | 8.78 | 50% |
| 沪 2000 | 13.34 | 8.96 | 47% |
| 沪 5000 | 13.66 | 9.83 | 72% |

## 5. 执行步骤（可复用）

沙箱副本 rsync（509 MB，SVN 工作副本零修改）→ 从 gt_svn 拷 3 个 CMakeLists → `patch -p4` 应用两处补丁（branch_id 归一化、NO_DSE 丢弃线程）→ `cmake -DFTE_NETCARD_TEST`（70 文件）→ `make -j10`（ute 171 MB、libutedatainit.so 25 MB，0 错误）→ 部署到 `gt_test_svn/run`（备份 gt_svn 产物）→ 功能深/沪 → 性能六档（各档统一 10 s 窗，样本 = TPS×10）。

交付物：`/home/lsz/code/work/gt_sit_src/DYS-FRAMEWORK`（沙箱源码）、`build_sit/fte/ute`、`build_sit/ftedatainit/libutedatainit.so`；原 gt_svn 产物备份为 `run/ute.bak_gt_svn`。

## 6. 六条教训

1. 远程手册里的机器相关项要本地验证（`BUILD_ARM=1` 本地反效果）。
2. SVN 分支可能缺第三方头文件（spdlog bundled 少 `core.h`）。
3. 性能测量前必须清残留进程——一个 188% CPU 的旧 FTE 就能把 outlier 推到 76%。
4. `pkill -f` 杀不掉守护进程，要按 PID。
5. 「静默排空」是用例串扰的正解，不是绕过。
6. 本地容器只适合功能验证，性能分位数必须用隔离大机。

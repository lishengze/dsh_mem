## 1. 删除「设计文档与图表」：四层一起清

删一个页签不只是删 HTML 面板——必须同步清四层，否则留下死路由或死自检项：

| 层 | 删除内容 |
|---|---|
| HTML (`static/index.html`) | 顶栏入口 `#docsLink`、首页面板 `#docsPanel` |
| JS (`static/app.js`) | `renderDocs()` 及健康自检中对它的调用 |
| 后端 (`server.py`) | `/api/docs`、`/docs/*`、`/diagrams/*` 三条路由 + `_serve_doc()`、`docs_dir()`、`list_docs()` |
| 元数据 | `/api/health` 的 `docs` 字段 |

验收用负向断言，比"看起来没了"可靠：
`/api/docs` → 404、`/docs/DESIGN.md` → 404、`/diagrams/architecture.html` → 404、
health 无 `docs` 键、首页源码中 `docsPanel`/`设计文档` 出现次数为 0。
设计文档本体（`web_ui/*.md`、`diagrams/*.html`）保留在仓库，只是不再由控制台提供浏览。

经验：**删面板要四层一起清**，只删前端会留下可访问的死路由，健康自检还会继续报旧字段。

## 3. 通路「已结束」暗化态（停止链路后整块置暗）

用户需求：停止深圳/上海链路后，把该市场框内**所有按键**设为暗色，表示这块区域操作已结束。

判定三条同时成立（`laneEnded(mk)`，`app.js` 约 146 行）：
1. 该市场**停止链路成功**；
2. 链路确已关闭（端口/进程探测为 down）；
3. 该市场当前没有任务在跑。

状态来源双保险：
- **即时**：任务结束时 `noteFinished()`（约 158 行）记账 `state.ended[mk]`，停止成功那一刻就变暗；
- **持久**：页面刷新/重开后从 `/api/runs` 取「该市场最新一条通路记录（start/func/capture/stop/all）」回推；
  内存只做加速，状态不因刷新丢失。
- `编译/部署` 等公共动作**不参与**判定，不会误把已结束的市场点亮。
- 解除：点该框内任一动作（启动链路/功能/性能/一键全流程）先清 `ended[mk]`，框立即恢复亮色，等结果再重新记账。

视觉（`.lane.done` + `.done-tag`）：中性背景 + 虚线边框（左侧强调色转灰）；标题灰化、圆点熄灭、右侧「已结束」胶囊；
5 个按键统一暗灰，压过成功蓝/失败红/链路绿/闪烁蓝，取消发光与动画，`opacity .72`，hover 才恢复可读；亮/暗两主题各自成立。

## 4. 坑与教训

1. **`var` 同名覆盖（本次自己引入）**：新常量命名为 `LANE_ACTIONS = ['start','func',...]`，与既有按钮定义数组
   `LANE_ACTIONS = [['start','启动链路'],...]` 同名，`var` 提升直接覆盖 → 所有通路按钮文案变成单字母
   （`'start'[1]='t'`，界面显示 `○ t`、`○ u`…）。改名 `LANE_ACTION_KEYS` 修复。
   教训：**改共用 JS 前先 grep 同名变量**；这类静默覆盖只有真跑界面才看得见，`node --check` 语法检查抓不到。
2. **门禁状态是易失的**：为解锁门禁需真跑一次编译（290.9s）+ 部署（2.4s），
   **重启服务会清零**，用户需重新点「编译」。交付时要把这条提醒带给使用者。
3. **推送被拒的处理**：远端先被推送（`e593130a8` 含 gt_svn 远程复测报告）→ `fetch` 后合并，
   `work_log/20261104.md` 冲突因双方都在文件尾追加任务块，按**两边都保留**（本机任务块在前、远端在后）解决，
   解决后 5 个任务块完整。合并类冲突优先保留双方内容，而不是二选一。

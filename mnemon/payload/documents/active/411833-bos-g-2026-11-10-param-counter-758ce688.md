## 1. 现象与映射关系

411833（`per_cust_risk_ctrl_set_processor_411833.cpp`）除 `custid/trdpwd` 外，另有 6 行 `TryGetValue("g_*")`。
这些键不是老系统 10 项公共入参，而是 **BOS 接口层对每个交易请求都会带的通用入参**（Java 侧 `BaseInstDTO`）：

| BOS `g_*` | 含义 | 对应老系统公共入参 | 性质 |
|---|---|---|---|
| `g_funcid` | 功能编号 | `funcid` | 同义，多一层前缀 |
| `g_operway` | 委托方式 | `operway` | 同义（BOS 传字符串，公共是 char(1)） |
| `g_operwayext` | 委托方式扩展 | `operwayext` | 同义 |
| `g_stationaddr` | 操作员站点号 | `netaddr` | 同义（名字不同） |
| `g_userinfo` | 用户信息 | `userinfo` | 同义 |
| `g_operid` | 操作员代码 | 无 | 仅用于操作日志 / `update_oper` |
| `g_estimated` | 设置校验位（`0`=连通性检查 / `1`=运行） | 无 | 控制「必填校验是否执行」 |

即 4 项是公共入参的 `g_` 前缀版（必须去重），2 项是无公共语义的 BOS 扩展项（须上提到框架承载）。

## 2. 为什么不能直接删这 6 行

- `m_nOperId` 会落操作日志与 `update_oper`：删掉后操作用户/站点全空，审计信息丢失。
- `m_cEstimated` 只余构造缺省值，`'0'`（连通性检查）语义丢失 → 连通性探活请求会误触发必填校验并报错。
- 结论：**解析上移到框架公共入参，业务只做拷贝**，既去重复又不改变对外行为。

## 3. 改法（3 个文件）

1. `otcsrc/lbm/lbm_otc_param/include/base_processor.h::GetGeneralParam()`：
   标准键优先解析，**为空再按 `g_` 键兜底**（`funcid←g_funcid`、`operway←g_operway` 取首字符、`operwayext←g_operwayext`、`netaddr←g_stationaddr`、`userinfo←g_userinfo`），
   并新增 `operid←g_operid`、`estimated←g_estimated`。与 query 基类已有的 `funcid←g_funcid` 兜底口径一致。
2. `otcsrc/lbm/lbm_otc_param/include/param_param.h`：`tagParamParam` 增加 `m_nOperId`（kdt_int）、`m_cEstimated`（kdt_char）两个 BOS 扩展字段，`Clear()` 同步复位。
3. `otcsrc/lbm/lbm_otc_param/src/processors/per_cust_risk_ctrl_set_processor_411833.cpp`：删除 6 行 `TryGetValue("g_*")`，改为纯拷贝，业务文件内不再出现任何入参键名：

```cpp
JSTP_STRCPY_S(m_szFuncId,      sizeof(m_szFuncId),      m_param.m_szFuncId);
JSTP_STRCPY_S(m_szStationAddr, sizeof(m_szStationAddr), m_param.m_szNetAddr);
JSTP_STRCPY_S(m_szUserInfo,    sizeof(m_szUserInfo),    m_param.m_szUserInfo);
if (m_param.m_cOperway != CHR_NULL) m_szOperWay[0] = m_param.m_cOperway; // 公共 char(1) → 业务 char(8)
m_nOperId    = m_param.m_nOperId;
m_cEstimated = m_param.m_cEstimated;
```

附带确认：`ParseInstructionData()` 是桩、不解析 `g_*`；`tagParamParam` 无跨模块引用，改结构体无 ABI 影响。
被注释掉的 `CHECK_STR_REQUIRED(m_szFuncId/…)` 的键名同步从 `g_*` 改回标准名，保留「本业务不强制必填」的说明。

## 5. 同类残留与下一批做法

`TryGetValue("g_*")` 仍存在：**param 31 个处理器**（cashprod_set / prodstatus_set / numsctrl_set / openday_set / arealimit_set / feerate_set …）、**counter 5 个处理器**（of_fast_out_cash_lmt_xjgj_set / of_sett_cash_abnor_deal / dzzh_manual_adjust / of_fast_out_cash_lmt_xjb_set / of_sett_cash_cancel_deal）；**query 已清零**。

批量处理套路（框架侧已就绪）：`grep -rn "\"g_" <模块>/src` 定位 → 删除业务解析行 → 改为「公共成员 → 业务成员」拷贝 → 按业务复测。注意同名前先确认是否触发「业务成员遮蔽基类字段」坑（见 `5d13fd14`… 与 §五·六）；凡是派生结构体重新声明了同名成员的，公共有值时必须 `JSTP_STRCPY_S` 显式拷贝。

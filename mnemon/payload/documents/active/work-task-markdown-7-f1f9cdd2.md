# 每日工作规划模板（work_task）纯 Markdown 简化版 final：结构与取舍

工作区：/home/lsz/code/work/work_store。本文记录 2026-11-04 在同一模板上从"内联 HTML 控件版"降级为纯 Markdown 可编辑版的最终结论，是 [@ff632d4e-d340-4c5c-9b3b-d0ab4b9efcf1] v1 控件基线的后续演进（原文档仍有效，描述的是被替换掉的 v1 形态）。

## 1. 最终产物

- 文件：`work_task/<YYYY>/<MM>/<YYYYMMDD>.md`（沿用年/月两级目录约定），示例当日文件 `work_task/2026/11/20261104.md`
- 体量：约 1.5 KB / 79 行（v1 控件版为 ~35 KB），纯 Markdown，无任何 HTML 标签
- 模板骨架源：`work_task/template.txt`

## 2. 结构（final 版）

1. 标题 + 星期 + 领域副标题
2. **一、目标设置**：工作 / 学习 / 生活 / 育儿 四个一级小节，各含两行
   `- 今日目标：` / `- 预期困难：`（冒号后留空直接输入）
3. **二、今日时间记录**：每 2 小时一段，共 7 行：09:00–11:00、11:00–13:00、13:00–15:00、15:00–17:00、17:00–19:00、19:00–21:00、21:00–23:00
   - 固定 6 列：时间 / 类型 / 工作性质分类 / 计划事项 / 实际经历 / 经验教训（含满意度 1–5 星）
   - 取值选项不放进控件，而是写在表格上方的引用块里：类型（工作/学习/生活/育儿）、工作性质（重要紧急/重要不紧急/不重要紧急/不重要不紧急）、满意度 1–5 星
4. **三、分类总结**：四个领域各一组 `**满意度**（不满意 / 还行 / 挺满意 / 很满意）：` + `**总结**：`
5. **四、今日总评**：用户自我总结（满意度 + 感受）、AI 总结（`*（待 AI 根据今日记录汇总）*` 占位）

## 3. 关键设计与理由

- **放弃内联 HTML 下拉框/输入框**：Markdown 预览里的表单状态不会写回 `.md` 源文件，用户若真要每天记录等于白填；改为纯 Markdown 后任意编辑器/Typora/VS Code 直接敲字即可。用户明确要求"取消所有下拉框和专门用于输入的框，直接让用户输入"。
- **Markdown 无法固定列宽**，只能影响自动分配。达成"类型列窄（约两个字）、计划事项/实际经历/经验教训三列宽"的做法是**加长这三列的表头文字**（如"计划事项（今日计划做什么）"），实测 860px 表宽下得到约 97 / 47 / 104 / 203 / 203 / 206 的列宽比例。副作用：表头变长，不同编辑器/窗口宽度下比例会漂移。
- **满意度只保留在上方提示与"经验教训"列标题里**，不再单独占列，避免表格过宽。
- 时段合并的说明文字放在表格上方的引用块（`> 11:00–13:00 为午间合并时段。`），不再用行内小字 span。

## 4. 复用时的验证清单（无头浏览器 + 文本自检）

- 文本自检：无 HTML 控件/无 HTML 标签、四段小节齐全、目标设置四领域各 2 行、时间行 7 行且顺序正确、6 列、合并时段提示存在、满意度四选项、用户总结与 AI 总结齐全、字节数与行数
- 渲染自检：打开本地 `file://` 预览后用 `document.querySelector`/布局读取表格实际列宽（`{w, cols, rows}`）确认窄/宽列比例符合预期，再截图确认
- 每次改动列宽或表头文字后须重新量列宽，纯 Markdown 的列宽对表头长度极其敏感

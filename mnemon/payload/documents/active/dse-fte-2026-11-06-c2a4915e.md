# DSE 启动依赖与 FTE 交互机制（研究记录 2026-11-06）

工程：`DYS-FRAMEWORK/fte/dse`（DSE，协议转换/路由节点）。同目录产出仓库内文档：
`DYS-FRAMEWORK/fte/dse/doc/dse_启动依赖与FTE交互_20261106.md`（154 行，5 章，提交 `a848995c5`）。

## 1. 启动是否需要"上场数据"：取决于节点角色

`DseDataLoader::Init()` 是唯一的数据入口，逻辑极简：

```cpp
DSEConfig::GetInstance()->Init();                 // 只读 dse.xml
if (DSEConfig::GetInstance()->is_credit_node) {   // 现金节点整段跳过
    CreditBizParamManager::GetInstance()->Init();
    StopStkCodeSecurityInfoManager::GetInstance()->Init();
    BizParam::GetInstance()->Init();
}
```

### 现金节点（`IsCreditNode=0`）：零业务数据

只需 `$ATP_CFG/dse.xml` + AMI 域服务器/端点配置，字段为
`InstanceName / UserName / UserPasswd / TargetIP / TargetPort / HeartBeatSecond / ConnectTimeOutSecond / ReConnectTime / IsCreditNode`。
`getenv("ATP_CFG")` 取不到或文件不存在 → `Init()` 返回 false → **启动直接失败**。

### 信用节点（`IsCreditNode=1`）：额外 3 个 `$ATP_DATA` XML

| 文件 | 读取方 | 关键字段 | 缺失后果 |
|---|---|---|---|
| `biz_param.xml` | `BizParam` | `TradeDay` | 安全，有判空跳过 |
| `credit_biz_param.xml` | `CreditBizParamManager` | `LongStopDays` 等 | **空指针崩溃**（未判空即 `get_child`） |
| `stop_stk_code_ute.xml` | `StopStkCodeSecurityInfoManager` | SecurityID/MarketID/StopDate/CalcuDate/IndustCode/IndustExponent | 安全，`ForeachXmlData` 宏有判空 |

关键机制：`XmlData::OpenXml(file, tree, bool allow_empty = true)` —— 默认允许缺失，只打 WARN 返回 `nullptr`。
**缺文件本身不致命，致命的是调用方没判空**。实测 FTE 测试数据目录 `test_all/etf_test_sh` 的 44 个 XML 中没有
`stop_stk_code_ute.xml`，印证现金节点场景不加载它。

### DSE 明确不负责的数据

资金/持仓/证券信息/账户/交易参数属 FTE（`libutedatainit.so` → `ftedata_init.cpp`）；
委托与回报状态为运行时经共享内存同步，不落盘。所以 DSE 上场数据需求极小：最多两个数值参数 + 一份停牌清单。

## 2. 与 FTE 的交互：共享内存 SPSC 双队列

两侧对称调用 `tech::external_data_sync::create(pro_name, con_name, size, spsc, time_out, heartbeat_milli, handler, …)`：

| 侧 | 调用点 | 参数 |
|---|---|---|
| FTE | `fte/src/main.cpp:443` | `create("ute_dse", "dse_ute", FTE_DSE_FIFO_LEN*4, fte_internal_spsc, 600, 5000, ext_handler)` |
| DSE | `dse/src/.../data_sync_engine.h:147` | `create("dse_ute", "ute_dse", DSE_UTE_FIFO_LEN*4, dse_internal_spsc, 600, 5000, handler_, state_sync_dse_handler_)` |

方向：**FTE→DSE 走 `ute_dse`，DSE→FTE 走 `dse_ute`**；信用节点另有行情队列 `ute_dse_md` / `dse_ute_md`。
容量：FTE 内部队列 65536 → 槽数 262144；DSE 8192 → 32768。超时 600 ms / 心跳 5000 ms 两侧一致。
`FTE_DEBUG` 构建下队列名追加登录用户名（`ute_dse_<user>`）。**任一侧 create 失败 → DSE `StopAmiApp()` 退出**。

### 消息类型

FTE→DSE（`tech::internal_msg_no`）：6 `kOrsSyncMsgNo`、7 `kOrsCacheOrderConfirm`、8 `kFTEExecutionReport`、
9 `kFTEBizReject`、10 `kFTEETFExecutionReport`、100 `kMarginTradeReport`、999 `kExit`。

DSE→FTE：AGW 协议号，进 FTE 的 `InsHandler::on_message`（下单 1001017、撤单 190007、ETF 101201、登录同步 10017），
行情类走 `ute_md_spsc`。DSE↔AGW/CTE 统一 `OrsPktHeader` + AMI 端点。
`business/external_data_handler.h` 的 `on_message` 是分流点：行情/额度类 msg_type
（`kPktDseMDInfoType`、`kPktGrcIssueSingleStkTotalScaleIns`、`kPktBssCreditStkScalePushInstruction`、
`kPktBssCreditPledgeStkQtyPushInstruction`）直接 push 进 `ute_md_spsc`，其余 dispatch 到 `InsHandler`。

### 四个作用

1. **协议桥接与路由** —— AGW/CTE 走 AMI/TCP，FTE 走共享内存，DSE 做转换。
2. **回报上行** —— FTE 成交/拒绝/ETF/两融回报经 DSE 转 AGW/CTE/ORS。
3. **回切与状态同步** —— 委托缓存确认 + 登录同步 + 自驱动心跳，保证 FTE↔CTE 回切不丢状态。
4. **控制指令与行情** —— 管理端实时控制指令经 DSE 下发；信用节点分发行情。

选型理由：FTE 是低延迟柜台，订单/回报路径不能过 TCP 栈；SPSC 无锁队列既保进程隔离与独立部署，
又把跨进程延迟压到接近内存拷贝。

## 3. 顺带发现的缺陷（值得修）

`dse/md/src/credit_biz_param_manager.cpp`：
```cpp
auto ptree_node_ptr = XmlData::Instance()->OpenXml("credit_biz_param", ptree_node);
for (auto& val : ptree_node_ptr->get_child("credit_biz_param")) { ... }   // 未判空
```
信用节点缺 `credit_biz_param.xml` 时不是可读报错而是空指针崩溃；`BizParam::Init()` 的写法（先判空）是正确范式。

## 4. 与测试构建的关系

测试构建用 `-DNO_DSE` 不带 DSE：不创建消费者，`fte_internal_spsc` 无人消费 —— 这是此前"5461 卡死"的根因
（上限 = 队列槽数 ÷ 每笔消息数）。沙箱补的"NO_DSE 丢弃线程"即在该场景模拟消费者。

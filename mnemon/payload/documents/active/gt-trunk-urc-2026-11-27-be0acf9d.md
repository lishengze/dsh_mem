## 2. 可直接复用的技术与环境硬事实

- **链路与端口**：客户端 →(TCP 33001/33002 或 SHM 三队列)→ FTE →(SHM SPSC)→ DSE；DS(25s)→DSE(28s)→FTE(95~100s)；
  mock 38140 / 39142 / **39143 现货** / 39144；控制台 8443。shm 应为 **6 个**，只剩 5 个 = DSE 已死。
- **两种部署形态不可混用**：`server`（49 aarch64 跑 FTE+DSE+DomainServer，42 x86_64 跑 mock+客户端；必须 cxx11、必带 DSE、禁 sudo、需 140 大页）
  与 `local`（同机，旧 ABI 可用、DSE 可选、性能测试暂不隔核绑核），统一入口 `deploy/envctl.sh`（只分派，不重复实现）。
- **报数口径纪律**：对外只报柜台侧（上行 2.85 µs、下行 4.08 µs、E2E 6.93 µs @1000TPS）；API 侧 3.75 µs 只用于评估优化幅度。
  同一优化会得到 **API −35.9% vs 柜台 −14%**（差 4 倍），混用即错。
- **环境铁律**：绑核与网卡必须同 NUMA（跨节点 +1.1 µs / +30%）；io 与 IRQ 同 NUMA 但不同物理核
  （同核 20.64 µs / 同 SMT 6.07 µs / 正确 3.00 µs）；`instanta_tcpdump` 绑不住，只能清残留；配对率 <90% 该轮作废。
- **API 侧最易错点**：撤单要填原委托响应里的 `client_order_no`；填 `orig_cli_ord_no` 恒为 0。
- **协议事实优先于编译报错**：`AgwMsgCustLoginResp` 的 `branch_id` 只在重复组 `fund_account_array` 元素里，顶层没有
  （登录**请求**有顶层 `branch_id`，**应答**没有）；后因上游给应答加了顶层字段，整段修复回退——说明「编译错误 → 协议事实 → 上游演进」三步都要核。

## 3. URC 优化现状（校正后的数字）

- 代码位置 `grc_trunk/DYS-FRAMEWORK/urc`（独立进程，276 文件 / 3.4 MB），文档 177~219 落在 `gt_trunk/svn_work`，与 §4.6 归属口径待确认。
- **端到端校正值**：空风控 31 620 ns / 2 规则 3 因子 38 070 ns / 生产风控（204 规则）110 820 ns。
  旧数据分别虚高 14% / 42% / **791%**（`217` 号的总表已被 `218` 号推翻）。
- **根因**：`/tmp/pin_final.py` 按 `utime+stime`（ticks）排序绑核，而 46 个线程 ticks 完全相同（3,320,134）
  → 排序结果随机 → 每次重启绑核布局都不同。**凡绑核脚本按 ticks 排序都要先验证 ticks 是否有区分度。**
- 另一类制表错误：把不同配置（空风控 vs 204 规则）的「优化前/优化后」并列，导致「优化后更差」的假象。
- 剩余最大项：**T2-1 → T2-2 队列跨核同步 ≈25.6 µs**（libadk SPSC 头尾同 cache line 伪共享，方向是同核或改布局）。

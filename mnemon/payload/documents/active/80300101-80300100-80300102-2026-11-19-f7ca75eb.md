# 数据加载阶段磁盘同步开关一律关闭（2026-11-19 新口径）

**仓库**：`otc_src`（提交 `e67bc64d feat(load): 数据加载阶段磁盘同步开关一律关闭，开启只走 80300300`，已推 `origin/dev`）
**权威正文**：`study/80300101_全局节点数据加载/80300101_全局节点数据加载_详细设计.md` §4.5、`..._测试案例.md` §八、`study/knowledge_base_system/03_全局节点开发.md`（数据加载阶段同步开关铁律）、`07_环境与排障.md` 第 10 条。
本文件是决策与证据摘要，细节以仓内文档为准。

## 1. 决策（新口径）

| 项 | 内容 |
|---|---|
| 关闭时机 | 加载/导入**开始前**关闭 → 结束后**无条件再关闭**（成功、失败、空 bin 放行三种结束方式一致） |
| 取消 | **删除 `RestoreTableDiskSync()`**，不再按 `sys_table_sync_cfg` 自动恢复为开 |
| 唯一开启入口 | **80300300**（内存表同步物理表开关设置） |
| 运维约定 | 上场数据加载完成后**必须执行一次 80300300**，配置为同步的表才会重新打开同步（写 OB） |

## 2. 动因（三条，可复用）

1. **加载期间清表 + 大批量写入**与 redo 同步并发，会产生「内存库有、OB 无 / 半量」的永久不一致，故必须先关。
2. **按配置恢复会让「是否同步」依赖加载时序与 `CalcTableSyncByCfg` 的兜底分支**：实测漏传 `bIsGlobal=true`，导致 `acc_cif_numband` / `otc_ofsaleslist` / `otc_bj` 三张表被误开；口径不可控。
3. **职责单一、可审计**：「加载」与「开关设置」两阶段分离，避免两处代码同时决定开关状态。

## 3. 改动清单（4 个文件，全局/业务各两份，改法一致）

- `otcsrc/lbm/lbm_jstp_system_global/include/imp_data_by_db.h`、`otcsrc/lbm/lbm_jstp_system/include/imp_data_by_db.h`
  - `CloseTableDiskSync()` 增 `szPhase` 参数（默认「导入/加载前」），置 false 后**用 `JstpGetTableOption` 回读校验**：读到 0 → INFO「磁盘同步开关已置关闭（回读=0）」；否则 WARN 带 setRet/getRet/回读值。
  - **删除 `RestoreTableDiskSync()`**（全仓无残留）。
  - **OB 导入路径**：`Close` 提前到「取得表句柄后立即」（原实现放在结构预检之后，预检失败直接 return，开关会保留上次可能为开的值）；成功尾部改 `Close(..., "导入结束")`。
- `otcsrc/lbm/lbm_jstp_system_global/include/system_data_imp.h`、`otcsrc/lbm/lbm_jstp_system/include/system_data_imp.h`
  - 文件加载（80300101 / 80300100）：成功、失败、空 bin 放行三条出口统一 `CloseTableDiskSync(..., "加载结束")` / `"空文件放行结束"`。

## 6. 坑与注意事项

1. **上线顺序风险（最重要）**：加载完成后若未执行 80300300，配置为同步的表**不会**写 OB。部署/运维流程必须保证「加载 → 80300300」的顺序，否则 OB 侧数据滞后。
2. **SVN 远端已被人改过**：两份 `system_data_imp.h` 提交时为 `M *`（远端 r78158/r78173/r78241/r78242 改过 `RegisterAllTables` 主键串，如 `acc_cif_firstbuy` 加 `cust_id`、`trd_oftafilec1` 改 `ta_code,fund_code`），与本改动区无重叠，但**提交前必须先 `svn update`**；命令见 `task_svn.txt` 组 14。
3. **行尾与 diff 最小化**：4 个 C++ 文件为 CRLF，删除函数后残留的多余空行会污染 diff，需清理（最终 +151/−77）。
4. **日志断言依赖新文案**：测试脚本按「磁盘同步开关已置关闭（回读=0）」匹配，改动文案会同时打断 19 项断言。
5. 环境侧既有噪声：kocadb 磁盘复制 keep alive 偶发单次 fail（前后 success，多为抖动）；多级跳板远程 shell 会在输出前打印 PATH，命令需用 `echo 'CMD_START'/'CMD_END'` 包裹后正则提取。

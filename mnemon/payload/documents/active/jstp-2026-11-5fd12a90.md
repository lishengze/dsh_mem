# JSTP 错误信息统计口径（参数对比「阶段四」）

> 适用范围：为 `study/<funcid>_<业务名>/<funcid>_参数对比.md` 末尾补「六、错误信息统计」章节。
> 一次批量实例：2026-11-04 完成 20 个业务 / 113 行（412230、240178、412231、411828、412232、410685、240690、411830、411827、411535、411833、411834、811526、831509、811509、410567、811523、410553、410233、811528）。

## 1. 核心口径（四参映射，最易错）

`JSTPAtomRaiseException(ErrorCode, ErrorLevel, EnglishTag, ErrorMsg)`

| 文档列 | 取自 | 说明 |
|---|---|---|
| 错误号 | 第 1 参 | — |
| 错误级别 | **第 2 参** | 本次样本全部为 `1`；无级别留空 |
| 错误信息 | **第 4 参**（中文提示） | 保留 `%s` / `%c` 等占位符原样 |
| 错误说明 | 人工归纳 | 触发条件 + 所在环节（主实现 / Atom 层 / 公共校验） |

易错点：把第 3 参（英文标识，如 `custid_empty`）当"错误信息"，或把 `JSTP_LOG_*` 日志枚举当"错误级别"。

## 2. 必查三类来源（漏一类就漏码）

1. **主实现 processor/business**：`JSTPAtomRaiseException` 直调点。
2. **Atom 层**：trade 类业务错误码大多在 `otcsrc/core/atom_counter/include/business/**/otcacc_business_*.h`（如 `otcacc_business_strategysign_cancel_240178.h`），主实现往往无抛错，错误全在此层及其基类 `RaiseWriteFailed`。
3. **被调用的公共校验**：`CheckCustomerAccount` / `CheckCustomerPassword` / `CheckTrdPwd` / `CheckCommParam` / `GenSnoInt` 等，会带来 `880211xxx`、`831509013`、`70240xxx001` 这类跨业务复用码。

## 3. 排除项（必须裁剪）

- **被 `//` 注释掉的抛错**：如 412231 头文件里 `412231030/035/037/040/041/050` 六处全被注释，属历史遗留，不进表。
- **框架级入参解析错误 `8000xxxx`**（如 `800028805` 入参未找到）：其"级别"实为日志枚举 `JSTP_LOG_LBM_PARAM`（`public/include/jstp_base_for_jstp.h`、`public/comm/kgbp_lbm_base.h`），与业务错误级别语义不同，统一不计入。
- 泛化文案不臆造：文档里出现的每个错误号必须在 `otcsrc` 能 grep 到。

## 4. 表格模板

```
## 六、错误信息统计（YYYY-MM-DD 补充）

> 统计口径：新框架实现 <相对路径> 中所有显式抛错（`JSTPAtomRaiseException(错误号, 错误级别, 英文标识, 错误信息)`）及被调用的公共校验错误码；
> "错误级别"取宏第 2 参，无级别时留空。框架通用入参解析错误（8000xxxx）不计入本表。

| 错误号 | 错误信息 | 错误说明 | 错误级别 |
|--------|----------|----------|:--------:|
```

规则：章节号唯一（全文只有一处 `## 六`）、按错误号升序、同级合并、单单元格不要过长（复用型错误号如 `880211799` 请压成场景摘要，否则表格渲染断裂）。

## 5. 机器校验清单（每轮都跑）

1. 格式：章节唯一、表头精确匹配、每行 4 列、信息/说明非空、无超长单元格。
2. 完整性：源码"活跃"错误码 ⊆ 文档（逐行跳过 `//` 注释行）。
3. 存在性：文档中每个错误号都能在 `otcsrc` grep 到 —— 无臆造。
4. 收尾自检：本轮无改动即可结束；有改动继续下一轮。

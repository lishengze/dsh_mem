# 800006 登入应答无顶层 branch_id：根因与双树修复（2026-11-26）

工作副本 `/home/lsz/code/work/gt_trunk`。修复已编译通过，**尚未提交**（提交需按三仓同步/ SVN 铁律由人执行）。

## 1. 根因（协议事实，最可复用的部分）

代码用了 `atp::gw::AgwMsgCustLoginResp::branch_id`，但该字段在报文里**不存在**。

`DYS-FRAMEWORK/gw_external_msg/V2/buildmsg/agw_external.xml:2132`（`pktno=800006 ver=2`）实际结构：

| 层级 | 字段 |
|---|---|
| `AgwMsgCustLoginResp`（顶层） | `client_seq_id`、`transact_time`、`cust_id`、`cust_name`、`permisson_error_code`、`fund_account_array`、`user_info`、`cif_account`、`fund_account_id` —— **无 `branch_id`** |
| `AgwMsgCustLoginRespFundAccountUnit`（重复组元素） | `fund_account_id` + `branch_id` + `fund_account_attr` + `account_array` + `credit_flag` |

要点：
- `branch_id` 只在重复组元素里；顶层 `fund_account_id` 在 AGW 侧 V2 处理器里**并未赋值**，因此定位资金账户应以重复组为准。
- `AgwMsgCustLoginReq` / `LogoutReq` 确实有顶层 `branch_id`——**登录请求能用，登录应答不能**。这是最容易凭印象写错的方向。
- map 的 key 是 `UTEFundAccountInfo_Key(fund_account_id, branch_id)`，所以两段信息缺一不可，只能从重复组取。

## 2. 暴露路径

- 引入：`62c52ec61 D:更新数据`（2026-11-24）新增网关模式登录流程 `deal_gateway_mode_cust_login_from_800006`，此前从未编译过，三处引用全部编译失败：
  `ute_client_handler_impl.cpp` 中建 key 与打日志各一处、`agw_client_impl.cpp:3456` 日志一处。
- `gw_api_boost` 与 `gw_api_no_boost` 的 `ute_client_handler_impl.cpp` 该函数**逐字相同**，boost 版此前没重编译所以未暴露。

## 3. 修法

不看顶层字段，改为遍历重复组逐个匹配（也贴合"一次 800006 可能带多个资金账户"的语义）：

```cpp
if (p->fund_account_array.empty()) { /* 打 kErrorLog 并返回 */ }
for (size_t i = 0; i < p->fund_account_array.size(); ++i) {
    const auto& unit = p->fund_account_array[i];
    UTEFundAccountInfo_Key key(unit.fund_account_id, unit.branch_id);   // 从重复组取
    auto it = ute_fund_account_info_map_.find(key);
    if (it == map.end()) { /* 打日志 continue */ }
    if (it->second.is_already_login_ute.load()) continue;
    // sendlogin_from_800006 用成员变量组包，先同步
    fund_account_id_ = it->second.fund_account_id;
    branch_id_       = it->second.branch_id;
    password_        = it->second.password;
    client_feature_code_ = it->second.client_feature_code;
    sendlogin_from_800006(p);
}
```

顺带修掉的隐藏缺陷：`sendlogin_from_800006()` 内部用 `this->fund_account_id_/branch_id_/password_/client_feature_code_` 拼 1001 报文，而网关模式下这些成员从未被赋值（只有直连 `set_cust_info` 才设），且原代码**没设 `password_`**——即使编译通过也会用上一个客户的凭据发登录。判断依据：`process_logon_ans` 里已登录标志按 `(fund_account_id, branch_id)` 落 map，修法与之一致。

第三处（`agw_client_impl.cpp` 日志）改为打印 `cust_id` + 循环输出重复组明细。

改动规模：4 文件 +102/−48（两棵树各两份：`ute_client_handler_impl.cpp` 60 行、`agw_client_impl.cpp` 15 行）。

## 4. 双树维护要求（工程事实）

- `gw_api_boost` 与 `gw_api_no_boost` 的 api/ute_api 源码长期逐字同源，**任何改动必须同时落两棵树**，否则下次重编译另一棵树时旧 bug 复活。

# 多轮复查协议落地 + check_doc_refs.sh（gt_trunk，2026-11-05）

> 出发点：原有规则只有三条抽象原则（"多轮复查、直到零修改"），执行时容易被解释成"看一遍就说没问题"。
> 本轮把它写成**可判定、可验证、可审计**的协议，并把最难肉眼查的一维（引用真实性）做成工具。
> 权威正文在 `task/task_rule.md` §3.1；工具用法在 `task/review/README.md` §七。本文记录设计口径与踩坑，避免后人重做。

## 1. 协议口径（§3.1 六个小节）

| 小节 | 作用 | 关键判定 |
|---|---|---|
| 3.1.1 三个定义 | 先对齐口径 | **一轮** = 对本轮**全部产出**完整过一遍（不是只看改动片段）；**零修改** = 没有任何一处要改（错别字/标点/路径过期/章节号错位/格式/冗余/过时结论/数字与证据不符）；**复查** = 验证，不是读一遍 |
| 3.1.2 流程 + 三条铁律 | 硬性不可裁剪 | 动了任何一处（1 个字符、1 个空格也算）→ 必须再开一轮**全面**复查；禁止只复查修改点；不允许口头判定通过 |
| 3.1.3 七维清单 | 每轮逐维过 | 正确性 / 完整性 / 一致性 / 可验证性 / **引用真实性** / 格式规范 / 无冗余过时 |
| 3.1.4 验证矩阵 | 按产出类型定必做项 | 代码=编译+跑；测试代码=必须能"红"（负向验证）；文档=路径 `test -e` + 章节号核对 + 命令可执行；SQL=执行+回滚；脚本=`bash -n` + 实跑；配置=加载一次 |
| 3.1.5 轮次登记 | 可审计 | 工作日志逐轮写"发现几处 → 改了什么"，收尾写"第 N 轮零修改"；**只写"已多轮复查" = 无效登记** |
| 3.1.6 明确禁止 | 反例清单 | 只复查修改点 / 用"看起来没问题"代替验证 / 以时间紧跳过必验项 / 一轮改完直接交付 |

另配 **§3.2 双轴审查**（Standards 轴：编码标准 + Fowler 坏味道；Spec 轴：是否实现需求）与 **§3.3 Fowler 十二种坏味道基线**。

| `task/task_all.txt` | 用户原始要求的第 4 条原文保留，其下补【口径】【登记】【禁止】【工具】四段 |
| `.chat/rules/project_rules.md` §3 | 面向所有会话的摘要版 |

## 3. check_doc_refs.sh：把「引用真实性」做成门禁

文档改版最常见的不是错字，而是"指针腐烂"——路径已删、章节号已位移，肉眼几乎查不出。工具检两类：

1. 反引号内的路径是否存在 → 报 `[PATH]`
2. `文件.md §N` 的章节号在目标文件是否真有该编号标题 → 报 `[SEC ]`

```bash
bash task/review/check_doc_refs.sh              # 默认文档集（规则/引导/记忆/索引）：约 1s
bash task/review/check_doc_refs.sh a.md b.md    # 只查本轮产出（每轮复查推荐）
bash task/review/check_doc_refs.sh --all        # 全仓 .md 体检：约 26s
bash task/review/check_doc_refs.sh -q           # 只输出问题
```

**退出码** 0=干净 / 1=有问题，可直接当收尾门禁或 CI 卡点。豁免项写进 `task/review/check_doc_refs.allow`，**每条必须写理由**——没有理由应去修文档而不是加豁免。
误报抑制：URL、本仓之外的绝对路径、占位符（`YYYYMMDD`、`<...>`、`*`、`~`、`…`）、数学式与配置式（含 `( ) = { }`）、系统头文件（`boost/*.hpp`、`unistd.h`）、裸扩展名（`.bin`/`.xml`）。

## 4. 四个踩坑（都值得记住）

1. **逐行 fork 子进程 = 性能灾难**。首版 `--all` 超过 180s 未完（字面 grep/sed 每行起进程）。改为纯 bash 解析 + 文件名索引缓存后降到 26s（默认集 0.98s）。慢工具没人会在每轮跑，等于没工具。
2. **新脚本权限 600 是历史踩坑点**。`task/review/` 下新文件建出来是 `-rw-------`，无执行位；已统一为脚本 755、清单/文档 644。交付脚本必须核对权限位。
3. **规则自身也会章节号漂移**。Round 1 复查抓到 2 处自引用错位（§3.1.1/§3.1.2 被写成 §3.1.3/§3.1.4）——正是本规则要防的问题，说明这类错误靠肉眼不可靠。
4. **工具必须能"报红"才算有效**。只证明"正常文档 0 问题"不够：需构造坏文件（坏路径 + `§99.9` 坏章节号）验证能报 `[PATH]`/`[SEC ]` 且退出码 1；同时验证空文件不崩、`-q`/`--help`/直接执行正常。

## 5. `--all` 的历史欠账（重要预期管理）

全仓扫描暴露约 200 处既有 `[PATH]` 问题，集中在 `tools/ai/big_file.md`（14）、`DYS-FRAMEWORK/fte/test_all/webui/MANUAL.md`（8）、`tools/ai/ana_*.md`、早期 `doc/` 下的代码引用，以及 `.bin`/`.xml` 等裸扩展名与系统头文件误报。
因此明文约定：**门禁只看本轮改动的文件**（`check_doc_refs.sh a.md b.md`），`--all` 仅作周期性体检，不因历史欠账阻塞当前交付。

3. **二、目标设置**：工作 / 学习 / 生活 / 育儿 四个小节，各两行 `- 今日目标：` / `- 预期困难：`。

5. **四、分类总结**：四领域各 `**满意度**（不满意 / 还行 / 挺满意 / 很满意）：` + `**总结**：`

## 3. 关键设计与理由

- **列宽只能靠表头文字长度影响 Markdown 自动分配**：用户要求"类型列窄到约两个字、计划事项/实际经历/经验教训三列加宽"，实现方式是给后三列写长表头（如"计划事项（今日计划做什么）"）；实测约 97/47/104/203/203/206 比例，删列后约 119/58/249/249/252（表宽约 929px）。副作用：表头冗长、跨编辑器比例漂移。参考依据：Typora 官方 Table-Editing 文档只提供 GUI 拖拽改列宽，Markdown 源无列宽语法。
- **行高与整体加宽用文末 `<style>`**：`table { width: 108% !important; margin-left: -4% !important; } table td { height: 64px; vertical-align: top; }`——用户要求"每行高度增加方便记录更多内容"。该 CSS 在 Typora / VS Code 预览生效，不支持内嵌 CSS 的编辑器（或 GitHub 渲染）看不到效果，需提示用户。
- **四象限用纯文本加冒号而非 `###` 标题**：用户明确"标题不用加粗，加个冒号"。纯文本行 + 空行即可直接书写，也避免了标题的视觉层级过重。
- **删除 `&nbsp;` 占位**：v2 曾用两行 `&nbsp;` 制造空白书写区，渲染成两个空 `<p>`（空格块）；用户要求删除后，四个小节仅剩标题行，空白由 Markdown 段落自然留出。教训：空白行分支测试（两段 `&nbsp;`、单段 `&nbsp;<br>&nbsp;`、纯 `<br>`）中，纯空行最干净，但会影响后续内容紧凑度。
- **保留纯 Markdown 可编辑**：延续 v2 结论——预览里的表单状态不会写回 .md，因此彻底放弃下拉框/输入框。

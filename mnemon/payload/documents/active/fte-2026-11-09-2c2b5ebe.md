# FTE 测试控制台：单案例运行、日志页与数据页（2026-11-09）

FTE webui 控制台（`DYS-FRAMEWORK/fte/test_all/webui/`）在任务4 中新增三项交互能力，并因此改动了 `run_test.sh` 的参数链路。原始实施记录见 `svn_work/70_任务4交互控制优化记录_20261109.md`；控制台多仓库与 /code 页的背景见文档 97e362f5，单案例目录与 DataTrans 背景见文档 0d85368b。

## 交付结构与入口

| 能力 | 入口 | 后端 |
|---|---|---|
| 指定案例运行 | 案例树右键菜单（唯一项「▶ 案例运行」） | `POST /api/case/run` → `server.py:_case_run` |
| 日志查看 | `/logs`（FTE(ute) → DSE → DomainServer 二级导航） | `GET /api/logs/tree`、`/api/logs/file` |
| 上场数据/配置查看 | `/data`（市场 → 数据/配置 → 文件 三级导航） | `GET /api/data/tree`、`/api/data/file` |
| 前端 | `viewer.js`（约 199 行） | 页面模块 `viewers.py`（约 323 行） |

单案例流程：右键 → `link_status()` 检查链路 → 未启动返回可读提示（`link_down`；若对侧市场在跑则提示先停该链路）→ 用基础测试配置生成**只含目标案例**的临时 test_config（`viewers.build_single_case_config`）→ 仅保留「功能测试」步骤并追加 `--config` → 提交异步任务。

## 关键踩坑（按出现顺序，均已修复）

1. **单案例任务不能复用整条动作模板**：模板含「停止链路」等步骤，会把刚检查通过的链路停掉。正确做法是只保留 `功能测试` 步骤，其余丢弃；若一个都没有则报 `no_step`。
2. **配置不能写到 run 目录**：`run_trunk/ute_mock_client` 属 root，宿主侧写入报 `Permission denied`。改为写控制台自有目录（`webui_results/single_case/`），再由 `plane.to_container_path` 转成容器路径。
3. **`--config` 会被 docker exec 吞掉**：`docker exec ... bash -c "..." --config X` 中的追加参数落在 `bash -c` 之后，不被目标脚本接收（表现为「未知参数：--config」）。必须把 `--config <path>` 拼进被执行的命令字符串内部。
4. **`run_test.sh` 把绝对路径拼到 MOCK_DIR 后**：原校验 `[ -f "${MOCK_DIR}/${CONFIG}" ]` 对绝对路径会拼出 `.../ute_mock_client//mnt/work/...`。修复为绝对路径直通（绝对路径不做前缀拼接）。
5. **run 目录可能部署的是旧版脚本**：改完 `run_test.sh` 后需重新 deploy 到 `run_trunk`，否则容器里执行的仍是旧脚本（曾因此多耗一轮排查）。
6. **mock_client 动态库**：二进制 RPATH 指向编译目录，异地不可用；运行前须 `LD_LIBRARY_PATH=<mock_dir>`（旧 API 库 libagw_ute_api/libagw_external_msg/libmsg_proto 与 mock_client 同目录）。缺库典型报错 `exit=127: libboost_system.so.1.62.0: cannot open shared object file`。
7. **退出码 135 / SIGBUS 属已知噪声**：mock_client 全局析构阶段偶发，此时报告与日志已完整落盘，不应据此判定用例失败。
8. **`server.py` 重构时丢变量**：`_case_run` 重写后 `steps` 未构建导致 `UnboundLocalError`（HTTP 连接被直接断开）。改该函数后应实跑一次接口而非只看启动日志。
